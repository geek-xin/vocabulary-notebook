# 设计文档：本地 HTML 下载 + 版本更新检查

- 日期：2026-09-18
- 状态：已实现
- 作者：geek-xin

## 一、背景

词汇本是**零构建单文件应用**：全部 HTML / CSS / JS 都在 `index.html` 里。但应用本身没有
「保存到本地」的入口——用户想把应用存到本机离线使用，只能靠浏览器菜单「另存为」，容易存下
一份带运行时痕迹、打开后状态错乱的副本。

同时，一旦用户把应用存到本地，这份副本就与线上彻底脱钩：线上修了 bug、加了功能，本地副本
不会有任何察觉，用户可能长期停留在旧版本。

本次改动提供的能力：

1. 首页右下角一行：**常驻版本号 + 「检查更新」+「下载」两个图标按钮**；下载一键把**纯净的
   应用本体**存到本地；
2. 本地副本打开时自动检查线上版本，发现更高版本就在这一行上方提示，并可直接下载新版；
3. 手动「检查更新」按钮，任何打开方式下都能查，且结果明确反馈；
4. 顺手精简「导入报告」的文案（见第六节）。

## 二、范围

| 项 | 结论 |
| --- | --- |
| 下载内容 | **只下载应用本体**（`index.html` 原文），**不含任何词汇本数据** |
| 下载后本地书架 | 为空。数据存在浏览器按来源划分的存储里，不随文件走，这是本方案已确认的取舍 |
| 更新对数据的影响 | **不覆盖、不影响本地词汇本**（更新只下载一个文件，不读写存储），见 5.7 |
| 按钮位置 | 仅**首页**右下角，学习页不显示 |
| 更新检测目标 | 线上 `index.html`（绝对地址写死在源码常量里） |
| 版本判定 | 源码里手动维护的 `APP_VERSION` 常量，与线上副本读出的值做数值比较 |
| 版本显示 | 首页右下角常驻 `v2026.09.18.1`，由 JS 从常量写入 |
| 数据结构 | 无改动。不新增存储键（更新提示的「已忽略版本」记录除外，见 5.5），不改动已存词汇本 |
| 现有分享功能 | 不改动 |
| 导入报告 | 只改文案（去内部细节、合并计数、短标题），不改统计口径与解析逻辑 |

**非目标**：不把词汇本数据内嵌进下载副本；不做 Service Worker / 自动覆盖本地文件；不改学习页；
不引入构建步骤或额外文件（不新增 `version.json` 之类）；不调整解析器的识别规则。

## 三、交付物一：右下角的版本号 / 检查更新 / 下载

### 结构

在 `#homeView` 内部、`.home-tip` **之后**新增一个竖列容器（`#homeView` 是 flex 列），
里面是一行「版本号 + 两个图标按钮」：

```html
<p class="home-tip" id="homeTip">…</p>

<div class="fab-stack" id="fabStack">
  <!-- 更新提示条由 JS 动态插入，位于这一行上方 -->
  <div class="fab-row" id="fabRow">
    <span class="app-version" id="appVersion"></span>
    <button class="icon-fab" id="checkUpdateBtn" type="button"
            aria-label="检查更新" title="检查更新">
      <svg …循环箭头图标…></svg>
    </button>
    <button class="icon-fab" id="downloadFab" type="button"
            aria-label="下载应用 HTML 到本地">
      <svg …下载图标…></svg>
    </button>
  </div>
</div>
```

两个按钮共用 `.icon-fab`，尺寸、配色、按下与焦点态完全一致；「检查更新」是**图形按钮**，
不带文字，靠 `aria-label` / `title` 表达语义。版本号是常驻的灰色小字，由 JS 从 `APP_VERSION`
写入（静态 HTML 里写死会与常量脱节）。

容器**不是** `position: fixed` 贴视口角落，而是作为首页 flex 流里的最后一项、`align-self: flex-end`
贴在卡片底部右侧。原因是实测发现视口角落的定位在窄屏会压住 `.home-tip` 那行提示文案，
详见下面「与首页底部文案的关系」。

提示条在这一行**上方**、同一列内（`flex-direction: column; align-items: flex-end; gap: 8px`），
因此提示条出现或消失**不会顶动按钮的位置**（只是让卡片内容整体上移一行）。DOM 顺序上提示条
插在这一行**之前**（`fabStack.insertBefore(pill, fabRow)`），与视觉上的上下关系一致。

### 显示范围

用 CSS 门控，不改视图切换逻辑：

```css
.fab-stack { display: none; … }
body.home-mode .fab-stack { display: flex; }
```

`renderHome()` 会加 `body.home-mode`，`openBook()` 会移除它，所以这一行天然只在书架页出现，
且首次渲染前不会闪现在错误位置。容器位于 `#homeView` 内，学习页下 `#homeView` 带 `hidden`，
是一层额外的保险。

### 尺寸与视觉

| 项 | 值 |
| --- | --- |
| 图标按钮 | 圆形 36px（`≤640px` 为 34px），图标 16px；两个按钮同尺寸 |
| 版本号 | 灰色 `#7f96ab` 12px（`≤640px` 为 11px），等宽数字，如 `v2026.09.18.1` |
| 位置 | `align-self: flex-end`，整行右边缘与首页内容区右边缘对齐，处在 `.home-tip` 下方 |
| 层级 | 不需要 `z-index`。它是普通流内元素，toast（`fixed`，999）与弹窗遮罩（`fixed`，1000）天然盖在它上面 |
| 配色 | 沿用玻璃拟态：`rgba(255,255,255,0.08)` 背景、1px 半透明描边、`backdrop-filter: blur(10px)`、`color: #cfe1f2` |
| 按下/悬停 | `:active` 加深背景；`@media (hover: hover) and (pointer: fine)` 下 hover 轻微提亮并上浮 1px |
| 焦点 | `:focus-visible` 用主题黄 `rgba(255, 217, 102, 0.42)` 描边，与搜索框聚焦态一致 |
| 禁用 | 检查进行中按钮 `disabled`，透明度降到 0.55 |
| 提示 | 下载 `aria-label="下载应用 HTML 到本地"`（`title` 另带当前版本）；检查 `aria-label`/`title="检查更新"` |

### 检查中状态

图标按钮没有文字，检查进行中用**图标匀速旋转**替代「检查中…」文案：按钮加 `.checking` 类，
配合 `@keyframes fab-spin` 旋转 0.9s/圈；`prefers-reduced-motion: reduce` 下改为降透明度，
不动画。

### 与首页底部文案的关系（实测后改成进入文档流）

首页底部有一行居中的小字（`.home-tip`）。实现后按验收要求实测了几何关系，结论是
**贴视口角落的定位会真实压住这行文案**，而不是仅仅盒子相邻：

| 视口 | 结果 |
| --- | --- |
| 375px | 提示条盖住文案第二行、按钮压住第一行右侧——文案被切成「点击词汇本开…／新打开依然可见」 |
| 1440px | 无碰撞（容器 `max-width: 1080px` 居中，按钮在容器右侧之外） |
| 推算 | 文案居中、宽约 400px，按钮/提示条从视口右侧 14px 起算，**视口窄于约 950px 就会真实重叠** |

曾考虑的两种「让位」方案都不成立：

1. 给 `.home-tip` 加右侧留白：提示条最宽 260px，375px 屏下内容区仅约 311px，留白后文案会被挤成
   一列窄字，观感更差；
2. 仅手机端改布局：重叠区间一直延伸到约 950px，平板同样中招，按设备分叉并不覆盖问题。

最终做法是让悬浮区**进入首页的 flex 流**（`align-self: flex-end`，排在 `.home-tip` 之后）。
这样在任何宽度下都不可能重叠，没有魔法数字、不隐藏任何内容，按钮依然是页面右下角的位置——
只是从「浏览器窗口的右下角」变成「应用卡片内容区的右下角」，与卡片圆角对齐后反而更整齐。

### 交互

点击 → 生成纯净 HTML（见第四节）→ 触发下载 → toast「已下载 vocabulary-notebook.html」。

## 四、交付物二：生成纯净的应用本体

### 取文策略：fetch 优先，快照兜底

```
prefetchSelfHtml()（页面加载后，仅 http/https 时执行）:
  1) 取 location.href 去掉 # 后的地址，fetch 它，把 response.text() 存进 selfHtmlText
     —— 拿到与服务器逐字节一致的原文，最干净
  2) 失败（file:// 下浏览器禁止 fetch 自身、离线、被拦截）就保持为空，静默降级

downloadAppHtml()（点击时执行）:
  1) 同步取用 selfHtmlText；为空则回退 snapshotSelfHtml()
  2) 两者都拿不到内容 → toast 报错，不产生文件
```

**取用必须同步**：如果改成「点击时才 fetch，在 Promise 回调里触发 `<a download>`」，
就跨了任务边界、丢失用户激活（transient activation），部分浏览器（Safari）会直接拦截下载。
预取在页面加载后空闲时进行，用户点击时通常早已就绪；万一没就绪就用快照——两条路径产出的
文件功能等价。

采用这个策略的原因：在线访问（GitHub Pages / 本地 http 服务）时，下载到的就是**线上那份原文**，
不会有任何运行时痕迹；只有在 `file://` 下打开本地副本、又要点按钮重新下载时，才走兜底路径。

### 兜底路径：用脚本执行时的 DOM 原文（`pristineHtml`）

`file://` 下浏览器禁止 `fetch` 自身，只能从 DOM 取。**不能**序列化「当前 DOM」——那里面已经有
用户数据了。做法是在 §2.9 区块的**第一条语句**抓一份 `document.documentElement.outerHTML`：

```js
const pristineHtml = document.documentElement.outerHTML;   // 此刻页面上还没有任何用户数据
```

这行必须满足两个前提，代码里有注释说明：它是本区块第一条语句，且脚本位于 `</body>` 之前。
此时解析器已消费完整个脚本，抓到的文档是完整的。

`snapshotSelfHtml()` 因此退化成一行——补上 DOCTYPE 后原样返回（若原文自带则不重复补）。

### 为什么必须这样：一次真实的数据泄漏

最初的实现是「克隆 DOM，逐项把运行时状态清回初始态」，清理表如下：

| 位置 | 处理 |
| --- | --- |
| `<body>` | 移除 `home-mode` 等运行时类 |
| `#bookGrid` | 清空 |
| `#homeView` / `#studyView` | 恢复可见 / 带 `hidden` |
| `#appTitle`、`#bookCount`、`#homeTip` | 恢复默认文案 |
| 确认框 / 导入报告弹窗 | 恢复 `hidden` |
| `#toast` | 清空文本 |
| 更新提示条 | 移除 |

这套清理**漏掉了两处会显示用户数据的地方**，实测确认副本里带出了词汇本内容：

| 泄漏点 | 带出的内容 |
| --- | --- |
| `#studyView` 内已渲染的字段 | 单词、音标、中英释义、例句、近义词/反义词（`renderWord()` 写过） |
| `#confirmText` | 删除确认框里的词汇本标题；`#reportText` 同理可能带出文件名与词条 |

实测：点进过一个词汇本、又打开过删除确认框之后下载，副本里 7 项用户数据全部命中。

逐项补漏只是把下一次遗漏推迟——凡是「新加了显示用户数据的元素」都会重新泄漏。因此改成抓初始
原文，**从根上不可能漏**，同时也删掉了整张清理逻辑。对应的断言脚本会种一个带唯一标记的词汇本、
打开它、再打开删除确认框，然后断言副本里不含标题/单词/释义/例句/近义词，`file://` 与 http 两条
路径都跑。

### 下载实现

`downloadHtml(text, fileName)`：`Blob`（`text/html;charset=utf-8`）→
`URL.createObjectURL` → 临时 `<a download>` 触发点击 → `URL.revokeObjectURL`。
文件名固定 `vocabulary-notebook.html`（比 `index.html` 更容易在下载目录里认出来）。

**副本不含词汇本数据。** 词汇本只存在浏览器存储里（IndexedDB → localStorage → 内存），
从不写进 HTML；两条取文路径（服务器原文 / 初始 DOM 原文）也都不含用户数据。

## 五、交付物三：更新检查与提示

### 5.1 版本号常量

脚本顶部常量区（与 `DB_NAME` 等并列）新增：

```js
const APP_VERSION = '2026.09.18.1';   // 发版时必须手动改这一行
```

格式 `YYYY.MM.DD.N`。**每次发布新版本都要改这一行**，这是本方案唯一的纪律成本；若忘记改，
本地副本不会收到更新提示。README 的「技术说明」里补一句发版提醒。

### 5.2 触发条件与时机

自动检查只在**本地副本**执行：

```
location.protocol === 'file:' || location.origin !== 'https://geek-xin.github.io'
```

此外：

- `navigator.onLine === false` 时直接跳过，省一次必然失败的请求；
- 首屏渲染完成后延迟 **1.5 秒**执行，不阻塞首屏、不与导入初始化抢网络；
- 在线访问时**完全不发**自动检查请求（用户已经在最新版上）。

一次检查 = 一次对 `https://geek-xin.github.io/vocabulary-notebook/index.html` 的 `GET`，
约 150KB。成本可接受，原因是：它命中浏览器 HTTP 缓存（线上 `cache-control: max-age=600`），
且**抓到的文本会被缓存下来直接用于「更新」下载，不会重复请求**。

之所以不做「只取文件头几个字节」的优化：`Range` 请求头不在 CORS 安全清单里，会触发预检，
而 GitHub Pages 不响应 `OPTIONS`，此路不通。

### 5.3 版本比较

`parseVersion(s)` 按 `.` 拆段转数字数组，`compareVersion(a, b)` 逐段数值比较（缺位按 0 处理）。
**仅当远端 > 本地**才提示——本地开发版比线上新时不会误报。

线上 HTML 里的版本号用正则读取：`/APP_VERSION\s*=\s*['"]([^'"]+)['"]/`。读不到（正则不匹配、
返回的不是应用页面、被网关改写）视为检查失败。

### 5.4 提示条

发现更高版本时，在版本号那一行上方插入持久提示条：

```
[● 发现新版本 2026.09.19.1]  [更新]  [×]
```

| 项 | 说明 |
| --- | --- |
| 视觉 | 玻璃拟态 + 主题黄圆点 `#ffd966` 表意「有新东西」，圆角胶囊 |
| 宽度 | `max-width: min(72vw, 260px)`，窄屏文案自动换行，不溢出屏幕 |
| 出现动画 | 淡入 + 上移 8px，`prefers-reduced-motion` 下取消 |
| 无障碍 | 「更新」「关闭」均为真实 `<button>`；关闭按钮 `aria-label="关闭更新提示"` |

### 5.5 两个动作的语义不同（关键）

| 动作 | 行为 |
| --- | --- |
| **更新** | 用 5.2 已抓取的文本直接调用 `downloadHtml()` 下载最新 HTML（缓存文本意外为空时重新 fetch），toast「新版本已下载，替换当前文件即可；词汇本数据不会丢失」。提示条**只在本次会话隐藏**（内存变量），旧文件没被替换，下次打开仍会提示——这是正确的 |
| **×** | 把该版本号写入 `localStorage`（键 `vn_update_ignored_version`），**永久不再提示这个版本**；线上出现更高版本时重新提示 |

「更新」后不做持久忽略，是因为持久忽略会让「下载了新版却没替换文件」的用户再也收不到提示。

### 5.6 手动检查（图标按钮）

图标按钮「检查更新」与自动检查共用同一个 `checkUpdate(manual)`，差别在准入与反馈：

| | 自动（`manual = false`） | 手动（`manual = true`） |
| --- | --- | --- |
| 触发范围 | 仅本地副本 | 任何打开方式，用户显式触发 |
| 离线判定 | 跳过 | 照常发起 |
| 有新版 | 提示条 | 提示条 + toast「发现新版本 …」 |
| 已最新 | 无反馈 | toast「已是最新版本（v当前版本）」 |
| 失败 | 仅 `console.warn` | toast「检查失败，请检查网络后重试」 |
| 已忽略的版本 | 不提示 | **重新提示**（`force` 打开提示条并解除本次会话静音） |
| 进行中 | — | 按钮 `disabled` + 图标旋转 |

手动检查能突破「已忽略该版本」，是因为忽略的语义是「别再自动打扰我」，而用户主动点击是一次明确
的询问，应当得到答案。

### 5.7 更新不会丢失本地词汇本

更新流程**只下载一个文件**，不读写任何存储。「更新」提示的文案也据此写明数据不会丢。

词汇本存在浏览器按**来源（origin）**划分的存储里，替换 HTML 文件动不到它。实测（系统 Chrome）：

- 本地文件的来源统一是 `file://`，在 `/tmp/a.html` 里写入的 localStorage 与 IndexedDB，
  工作区里的 `index.html` 能原样读到；
- 因此换文件名、换目录、用新版本文件替换旧文件，词汇本都还在。

端到端验证脚本会：让应用自己存下一个词汇本（走「旧 localStorage 键 → 迁移进 IndexedDB」的真实
路径）→ **删掉旧键，只留 IndexedDB**（否则后续导航会靠旧键重新迁移，掩盖真实的数据丢失）→
触发更新下载 → 用新文件替换旧文件 → 重新打开 → 断言词汇本数量与标题完好、且打开的确实是新版本。

⚠️ 一个需要写进文档的边界：若改用**本地 http 服务**打开副本，来源从 `file://` 变成
`http://localhost:…`，书架会是空的。README 因此明确要求「始终用 `file://` 双击打开」。

### 5.8 失败一律静默（仅指自动检查）

离线、超时（`AbortController` 8 秒）、跨域被拒、正则读不到版本号、`localStorage` 不可用
（`file://` 下 Safari 可能禁用，`try/catch` 降级为仅本次会话记住）——自动检查全部只
`console.warn`，不弹任何提示。自动检查是锦上添花，不能打扰学习；手动检查则必须有反馈，见 5.6。

## 六、交付物四：精简导入报告

导入完成后弹出的「导入报告」原本把内部算法细节也写给用户看，计数还逐行铺开。只做「去噪音」，
信息量不减：

| | 改前 | 改后 |
| --- | --- | --- |
| 计数 | `解析成功：12 条` / `（整篇扫描 12 条 / 逐段解析 10 条，取较多者）` / `重复合并：2 条` / `未识别：3 条` 四行 | `解析成功 12 · 合并重复 2 · 未识别 3` 一行 |
| 小节标题 | `重复的单词：` / `未识别的行（最多 40 条）：` / `识别失败的内容：` / `失败的文件：` | `重复单词` / `未识别（最多 40 行）` / `无法识别` / `失败文件` |
| toast | `已导入 2 个词汇本（24 词），1 个文件失败，重复合并 2 条，未识别 3 条（见导入报告）` | `已导入 2 个词汇本 · 24 词 · 未识别 3 行（见报告）` |

具体做法：

- 删掉「整篇扫描 / 逐段解析，取较多者」——这是解析器内部的两种扫描策略取并集，对用户是噪音；
  随之删掉只服务于这一行的 `inlineTotal` / `blockTotal` 两个累加器（避免留死代码）。
- 摘要行按需拼接：只有非零项才出现（「合并重复」「未识别」「失败」）。
- 小节仍然只在有内容时出现，明细列表仍保留编号与条数上限。

**可验证性**：报告拼装从导入处理函数里抽成纯函数 `formatImportReport(stats)`，入参是一个普通对象、
返回字符串，不碰 DOM。这样既能用构造数据逐字断言文案，也能在真实导入里走同一条代码路径
（导入处理函数只负责收集统计再调用它）。

## 八、验收标准

1. 首页右下角出现版本号与两个同尺寸圆形图标按钮（检查更新、下载），学习页都不出现；
   按钮位置不被更新提示条顶动。
2. 版本号显示为 `v` + `APP_VERSION`，与源码常量一致。
3. 点击下载得到 `vocabulary-notebook.html`，内容以 `<!DOCTYPE html>` 开头，含 `<style>`
   与完整脚本。
4. 下载的副本**不含任何词汇本内容**：在「打开过某个词汇本、又打开过删除确认框」之后下载，
   副本里不含该词汇本的标题、单词、中英释义、例句、近义词——`file://` 与 http 两条路径都成立。
5. 用 `file://` 打开下载下来的副本：空书架正常显示，导入词汇本、学习、分享等原有流程可用。
6. 本地副本（如 `file://` 打开）在 1.5 秒后自动检查线上版本；线上版本更高时，版本号那一行上方
   出现「发现新版本 … · 更新 · ×」提示条。
7. 线上版本不高于本地、或自动检查失败（离线 / 超时 / 读不到版本号）时，**不出现任何提示**，
   仅控制台告警。
8. 点「×」后重新打开该本地副本，不再提示同一版本；但**手动点「检查更新」会重新提示**。
9. 手动点「检查更新」：有新版给提示条 + toast；已最新给「已是最新版本（v…）」；失败给
   「检查失败，请检查网络后重试」；进行中按钮禁用且图标旋转。
10. 点「更新」下载到线上最新 HTML，toast 说明替换文件即可、数据不会丢失；当前页面提供的仍是旧版本。
11. 用新版本文件替换旧文件后重新打开，**本地词汇本仍在且内容完好**。
12. 从线上站点访问时（origin 为 `https://geek-xin.github.io`），不发起任何自动检查请求。
13. 320 / 375 / 480 / 640 / 768 / 1024 / 1440 / 1920px 等下，版本号那一行与更新提示条均不溢出、
    不与首页底部文案、卡片、toast 重叠；弹窗打开时被遮罩盖住。
14. 键盘可依次聚焦「检查更新」「下载」与提示条上的两个按钮，焦点样式可见；两个图标按钮都有
    可读的 `aria-label`。
15. 导入报告：计数合成一行、不再出现「整篇扫描 / 逐段扫描」、小节用短标题；真实导入一个含重复词
    与未识别行的 `.docx` 后，报告与 toast 均符合上表。
16. 现有分享、导入、搜索过滤、学习流程不受影响。

## 九、验证方式

项目为零构建单文件应用、无测试框架，采用系统 Chrome + Playwright 实测：

1. **下载链路**：监听 `download` 事件捕获产物，校验文件名与内容（含 `APP_VERSION`、不含
   卡片 DOM、`#studyView` 带 `hidden`）。
2. **数据泄漏**：种一个带唯一标记的词汇本，打开它并打开删除确认框，再下载，断言副本里不含
   标题 / 单词 / 中英释义 / 例句 / 近义词；`file://` 与 http 两条路径都跑。
3. **更新提示**：用 `page.route()` 拦截线上地址，返回一份伪造的高版本 HTML，验证提示条出现、
   「×」后重开不再提示、「更新」确实下载出新版本；再拦截为相等/更低版本，验证不提示。
4. **手动检查**：把应用伪装成部署在线上域名（`isLocalCopy()` 为 false、自动检查不跑），
   以此隔离出「提示条只可能来自手动点击」；再覆盖已最新、失败、进行中、突破已忽略四种情况。
5. **失败静默**：拦截为超时或非应用页面，验证自动检查无任何提示且无报错弹窗。
6. **更新不丢数据**：让应用自己存下词汇本并删掉旧 localStorage 键（只留 IndexedDB），
   触发更新、用新文件替换后重新打开，断言词汇本数量与标题完好。
7. **视觉与层级**：320～1920px 共 11 个宽度下测量几何关系，断言无重叠、无溢出；弹窗打开时
   按钮被遮罩盖住。
8. **导入报告**：纯函数逐字断言文案；再造一个含重复词与超长未识别行的 `.docx`，走真实导入
   验证报告弹窗与 toast。
9. **回归**：在下载下来的副本上重跑导入、学习、搜索、分享流程。
