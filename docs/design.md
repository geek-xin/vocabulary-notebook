# 设计文档

> 描述**当前**架构与关键取舍。与代码冲突时以代码为准。
> 需求与计划不写在这里；历史变更见 [history.md](history.md)，多端交付见 [multi-platform.md](multi-platform.md)。

## 1. 总览

「词汇本 · 多词库学习」是一个**单文件、零构建**的英语词汇应用：导入 `.docx` / `.pdf` / `.txt` 词表，
提取英文词条后由**在线词典**补全音标、词性、中英释义与近反义词，再以卡片形式学习。

产品本体只有 `index.html` 一个文件，内含全部 HTML / CSS / JavaScript，无框架、无打包器、无依赖安装。

> 界面可离线打开（PWA 外壳已缓存），但**释义全部来自在线词典**，断网时新词补不上释义。

### 为什么是单文件

拆分文件会同时破坏「双击即用」与「下载一个 HTML 就拿到完整应用」这两点。
`file://` 下浏览器会拦截 `fetch` 本地文件、限制 ES module，拆开就得起 http 服务，
而目标用户（手机 + 微信传文件）没有这个条件。因此不做拆分。

### 运行方式

| 场景 | 说明 |
| --- | --- |
| 在线 | `https://geek-xin.github.io/vocabulary-notebook/`；手机可「添加到主屏幕」 |
| 本地单文件 | `file://` 双击打开；来源统一是 `file://`，换文件名/目录仍读同一份数据 |
| 原生壳 | Android（`https://localhost`）、iOS（`capacitor://localhost`） |

### 版本号纪律

`APP_VERSION`（`YYYY.MM.DD.N`）是判断版本新旧**唯一依据**，必须与 git tag 对应。
发版用 `node scripts/set-version.mjs <版本>` 一处写入五处，不要手改。
CI 会校验 `APP_VERSION` 与 tag 一致，不一致直接失败。

## 2. 数据模型与存储

### 数据模型

```js
词汇本 Book = { id, title, words: Word[], createdAt, ... }
Word = {
  word,        // 词条原文（保留源文件拼写）
  pos,         // 词性，如 "n./v."；短语为 "phrase"
  phonetic,    // IPA 音标，来自 Datamuse 的 ARPAbet 转换
  meaningEn,   // 英文释义
  meaningCn,   // 中文释义；缺省填 '—'
  synonyms: [], antonyms: [],
  example      // 当前恒为空，见 §5
}
```

`meaningCn` 为 `'—'` 是「尚未补全 / 在线词典查不到」在 UI 上的表现，不是解析失败。

### 三级存储降级

`storage` 对象封装三档，按可用性自动选择：

| 优先级 | 实现 | 触发降级的条件 |
| --- | --- | --- |
| 1 | IndexedDB（`vocabulary_notebook` / `kv`） | — |
| 2 | localStorage | 无 `indexedDB`、打开失败、被阻塞、超时 |
| 3 | 内存 | localStorage 探测写入失败 |

内存模式下刷新即丢数据，应用会明确提示。

### 旧数据迁移

旧版本把词汇本存在 `localStorage`（键 `vn_books_v1`）。首次打开时若 IndexedDB 可用，
会自动迁移并记录日志。

## 3. 导入与解码

### 类型识别

按扩展名与 MIME 分流到三条路径：`.docx` → mammoth、`.pdf` → pdf.js、`.txt` → 纯文本解码。

### 按需加载解析库

解析库只在真正导入对应类型时才从 CDN 加载，并按序回退：

```
mammoth:  jsDelivr → BootCDN → staticfile → cdnjs
pdf.js:   jsDelivr → BootCDN → cdnjs（含 worker）
```

`loadScriptOnce` 缓存已成功的 URL，避免重复注入；全部失败才报错。

### 纯文本解码 `decodeTextBuffer`

`.txt` 不依赖任何 CDN，因此**离线可用**。编码识别顺序：

1. UTF-8 BOM → UTF-8
2. UTF-16 LE/BE BOM → 对应编码
3. 无 BOM：先按 UTF-8 解码，若出现替换字符 `\uFFFD` 则回退 **GBK**

### 导入行为

导入完成后延迟 800ms 启动在线补全，**不阻塞导入**。
导入报告会明确列出解析条数、重复合并数、未识别行数（最多列 40 行），而不是静默少词。

## 4. `parseWordList` 双路解析

同一份文档用两种方式各解析一遍，取**词条更多**的那一路：

| 路径 | 做法 | 擅长 |
| --- | --- | --- |
| A 整篇扫描 | 把全文拼成一行，用 `NUMBERED_RE` 找编号切分 | 跨段落、表格 |
| B 逐段解析 | 逐块处理 | Word 自动编号（`<li>` 无序号） |

两路都会去重（`seen` 集合），并记录 `duplicates` / `rejected` / `unused` 供导入报告使用。

### `plain` 模式（`.txt`）

一行即一个词条，不走编号切分。这样能正确处理「一行一个单词」的简单词表，
也避免把含数字的单词误切。

### 词条清洗

`pushEntry` 对每个候选做：截断到首个中日韩字符之前 → 去掉首尾标点/符号 → 去掉行尾序号 →
压缩空白。必须以字母开头，否则计入 `rejected`。

**不做词形回退匹配**（前缀/词干/后缀），因为会产生危险假阳性：
`per→permit`、`operate→opera`、`temper→temperature`、`lately→latest`、`sign→sign up`。
取舍是**原词直查在线词典**，不猜词形。

## 5. 词典：全部在线

**应用不内置任何词库。** 导入后每个词条先建成空卡，再由在线词典在后台补全。

| 信息 | 来源 | 通道 |
| --- | --- | --- |
| 中文释义、词性 | 有道 `suggest` | JSONP（接口无 CORS 头，但支持 `callback`） |
| 英文释义、近反义词、音标 | Datamuse `api.datamuse.com` | `fetch`（CORS，含 `null` origin） |

### 为什么去掉内置词典

内置词典曾有 731 条、183.7 KB，占 `index.html` 的 **55%**。两个长期问题：

1. **覆盖率永远不够**：任何真实词表都会大量未命中（「真题 1 校园版」91 词里只命中 8 个），
   于是又叠一层联网兜底 —— 两套来源、两套优先级，复杂度翻倍。
2. **维护成本高**：为补词要手工校对音标、释义、例句，词典越补越大，命中率提升却有限。

去掉后 `index.html` 从 330 KB 降到约 152 KB，导入路径只剩一条：建空卡 → 在线补全。

### 音标：ARPAbet → IPA

Datamuse 的 `tags` 里带 `pron:S EH0 R AH0 N D IH1 P IH0 T IY0`，是 **ARPAbet 音素**而非 IPA，
必须经 `arpabetToIpa()` 转换。

映射本身是一对一，难点在**重音符号的位置**：它属于整个音节，要放在**音节首**。
直接放在元音前会得到 `/prˈaɪs/`，正确的是 `/ˈpraɪs/`。
因此先按「最大音节首」原则（`onsetOf()` + 合法辅音簇表 `ONSET2` / `ONSET3`）把元音之间的
辅音簇切给下一音节，再把符号放到该音节开头。词首辅音簇整体归本音节，
因为英语没有以 `/str/` 这类三辅音结尾的音节。

| 词 | ARPAbet | 转换结果 |
| --- | --- | --- |
| price | `P R AY1 S` | `/ˈpraɪs/` |
| serendipity | `S EH0 R AH0 N D IH1 P IH0 T IY0` | `/sɛrənˈdɪpɪtiː/` |
| furniture | `F ER1 N IH0 CH ER0` | `/ˈfɜːrnɪtʃər/` |
| competition | `K AA2 M P AH0 T IH1 SH AH0 N` | `/ˌkɑmpəˈtɪʃən/` |
| instruction | `IH2 N S T R AH1 K SH AH0 N` | `/ˌɪnˈstrʌkʃən/` |

> ⚠️ 这是**美式**发音的机械转换结果，未经人工校对。

### 补全流程

- **只补空字段**：已有内容永不覆盖。
- **不阻塞导入**：导入完成 800ms 后后台执行；启动 3s 后对已有词汇本再做一次后台回填
  （每次上限 `DICT_BACKFILL_MAX = 400` 词）。
- **并发 4**（`DICT_CONCURRENCY`），单请求 8 秒超时（`DICT_TIMEOUT`）。
- **按词缓存** `vn_dict_cache_v1`：上限 4000 条、TTL 180 天。
  命中缓存时**直接把缓存内容填进卡片**，而不是跳过 —— 见下。
- **只缓存「有应答」的结果**：两个来源都是网络失败时不落缓存，下次仍会重试。
- **失败降级**：`navigator.onLine === false` 或接口全挂时保持空卡，不弹错误、不影响导入。

#### 缓存命中必须写入词条（曾是个真实 bug）

`enrichWords()` 原先把「缓存里有新鲜结果」当成「无需处理」直接 `continue`，
**从不把缓存写进词条**。后果：同一个词第二次导入（或换个词汇本导入）时，
缓存明明有数据，卡片却永远空着。

内置词典时代这个问题被掩盖了（多数词命中词典、不走联网路径），去掉词典后它会让大量卡片无故空白。
现在命中缓存会直接 `applyOnlineEntry()` 填卡 —— **缓存只省网络请求，不省「写入」这一步**。

### 能力边界

- **没有例句来源。** 可跨域的免费接口都不提供例句，所以例句区块在无值时**整块隐藏**
  （`renderWord` 里控制 `frontExampleBox` / `backExample` 的 `hidden`）。
  数据最全的有道 `jsonapi`（含 IPA 与双语例句）**既无 CORS、加 `callback` 还返回 403**；
  `fsearch` 是 XML 且带 `Origin` 时 403；`api.dictionaryapi.dev` 在目标网络不可达；
  Tatoeba 302 重定向且返回 HTML。将来接上可用来源会自动恢复显示。
- **音标是美音近似值**，机械转换、未经校对。
- **关闭联网开关后没有任何本地兜底**：`localStorage` 的 `vn_online_dict_v1 = '0'` 会禁用补全，
  此时**所有卡片都是空的**。该开关只适合受限网络下临时禁用外部请求。

## 6. 深色 / 浅色主题

- 首帧由 `<head>` 里的内联脚本按 `localStorage`（`vn_theme_v1`）/ 系统偏好写到 `<html data-theme>`，
  避免闪烁。
- 用户没手动选过时跟随系统，系统主题变化实时生效；选过就持久化。
- 切换时同步更新 `<meta name="theme-color">`（深色 `#0f1724` / 浅色 `#eef4fb`）与按钮 `aria-label`。

## 7. 学习页交互与发音

### 卡片

点击卡片翻转（正面：单词/词性/音标/中英释义；背面：音标·词性/近反义词/例句）。
左右方向键切换上/下一张。空字段统一显示 `—`。

### 进度

每个词汇本独立记录上次阅读位置（`vn_progress_v1`），重新打开自动回到原位。
点击计数器可直接输入页码跳转。

### 发音

`https://dict.youdao.com/dictvoice?audio=<word>&type=1`（`type=1` 为**英式**）。
**不要**给 `audio` 设 `crossOrigin`，否则会触发 CORS 检查导致加载失败。

> 注意口音不一致：发音音频是英式，卡片上的 IPA 音标来自 Datamuse、是美式。

## 8. 首页与查询

- 书架以卡片网格展示每个词汇本，支持删除与分享。
- 搜索框按**词汇本名称**或**单词内容**过滤。

## 9. 分享

把单个词汇本打包成一个**独立 HTML**：复用本页样式与卡片结构，内嵌该词汇本的全部数据，
生成的文件离线可打开。移动端优先走系统分享（可发微信），否则回退下载。

所有写入分享页的数据都经 `escapeHtmlText` 转义，JSON 里的 `<` 替换为 `\u003c`，
避免词条内容破坏分享页结构。

## 10. 下载应用本体与更新检查

### 下载：取文两条路径

1. **在线**：`prefetchSelfHtml()` 空闲时抓 `location.href` 原文缓存备用；
2. **`file://`**：浏览器禁止 fetch 自身，回退到脚本执行时留下的 `pristineHtml`（`document.documentElement.outerHTML`）。

取用必须**同步**：异步会丢失用户激活，部分浏览器会拦截下载。

### 为什么用「初始原文」而不是「克隆 DOM 再清理」

`pristineHtml` 抓取时刻**早于任何用户数据进入页面**（词汇本卡片、学习页词条、弹窗文案都还没渲染），
所以副本天然不含词汇本内容，无需逐项清理。这条依赖脚本位于 `</body>` 前且该语句是本区块第一条语句。

### 更新检查

两条通道，Release 优先：

1. **首选** `GET /repos/geek-xin/vocabulary-notebook/releases/latest` —— 读 `tag_name` 与 `assets`；
2. **回退** 抓线上 `index.html` 正则取 `APP_VERSION`。

必须回退的场景：GitHub API 未认证限流（60 次/小时/IP，返回 403）、仓库尚无 Release（404）、
离线、8 秒超时。回退再失败时，只有**手动**检查才提示失败，自动检查全程静默。

**自动检查的覆盖面**（`shouldAutoCheck()`）：

```js
function shouldAutoCheck() { return isNativeShell() || isLocalCopy(); }
```

这里有个容易踩的坑：`isLocalCopy()` 在原生壳内返回 `false`（壳确实不是「本地副本」），
若直接拿它当门槛，**壳内会永远收不到更新提示** —— 而壳正是移动端的主要分发形态。
线上 Web 端仍然跳过自动检查，那里由 Service Worker 负责更新。

**壳内的忽略策略与 Web 端不同**：**不落盘** `APP_IGNORED_KEY`，忽略只对当次会话生效。
理由是壳内用户既不能刷新页面也不能替换文件，提示条是唯一的更新入口；
持久化忽略会让用户随手一关就永久失联。

### 更新不会丢词汇本

词汇本存在按来源划分的本地存储里，替换 HTML 文件本身动不到它。
本地副本请始终用 `file://` 打开：来源统一，换文件名/目录仍读同一份数据；
改用本地 http 服务则来源变化，书架会变空。

## 11. 边界与不做的事

### 明确不做

| 不做 | 原因 |
| --- | --- |
| 拆分为多文件 / 引入构建步骤 | 破坏「单文件、双击即用、下载一个 HTML 就是完整应用」的核心定位 |
| 词形回退匹配（前缀/词干/后缀） | 会产生 `per→permit`、`operate→opera` 这类危险假阳性；改为原词直查在线词典 |
| 内置词典 / 压缩分包词典 | 已整体移除（见 §5），改用在线查询 |
| 联网结果覆盖已有内容 | 只填空字段，用户看到的内容永不被后台请求改写 |
| 手工补全 UI | 卡片仍不可手工编辑；释义由在线词典自动补 |
| 例句 | 当前没有可用的免费跨域来源，区块隐藏而非显示空 `—` |
| 云同步 / 账号 | 数据只存本机，不上传任何服务器 |

### 需要记住的取舍

- **空卡是正常的**：导入瞬间所有词条都是空卡，在线补全随后填上；查不到的词保持空卡，
  这不是解析失败。判定「解析是否成功」看导入报告里的解析条数与未识别数，而不是卡片是否有释义。
- **在线补全只补空字段**：离线或接口失败时完全跳过，不阻塞导入，下次联网自动回填。
- **各端数据互相独立**：按 origin 隔离，升级安装包不丢数据，但换端不会自动同步。
- **只做 Web / Android / iOS 三端**：鸿蒙端曾在 2026.09.30.1 加入、2026.10.01.5 移除，
  原因是它需要独立的 ArkTS 工程与另一套工具链（CI 依赖第三方 2.1 GB SDK），
  维护成本与收益不成比例。旧版鸿蒙仍可直接安装 Android APK。

## 12. 验证约定

- **代码是唯一事实来源。** 文档与代码冲突时以代码为准，并尽快修正文档。
- 可自动化的验证都进了 `scripts/`，由 `npm test` 与 CI 执行：

| 脚本 | 检查内容 |
| --- | --- |
| `check-inline-js.mjs` | 抽取 `index.html` 内联脚本做语法检查（用 `vm.Script`，能正确拒绝顶层 return/import） |
| `test-sw.mjs` | 在 Node 里用假 ServiceWorker 作用域跑 `sw.js`，断言预缓存与拦截策略 |

- **真机行为无法在本机验证**，各端验证边界见 [multi-platform.md](multi-platform.md) §8。
- **子智能体的自检不能当验证**：自检只是「我以为对了」，必须用独立校验器或真实运行核对。
