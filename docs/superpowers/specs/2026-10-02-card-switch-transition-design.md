# 切换卡片词汇时的过渡动画 — 设计

**日期**：2026-10-02
**状态**：已与用户确认，待实现

## 1. 背景

学习页切换卡片时，`renderWord(index)` 把新旧内容原地替换，卡片没有任何过渡，
视觉上是「文字瞬间跳变」。四个切换入口（随机切换、顺序切换、← → 方向键、点击「1 / N」输入页码跳转）
都是这个观感，切换时缺少方向感 —— 用户分不清是翻到了下一张还是上一张。

用户要求：**切换卡片词汇时增加过渡动画。**

## 2. 目标

- 四个切换入口在切换时播放方向感知的过渡动画：下一张从一侧滑入、上一张从另一侧滑入。
- 在卡片背面时切换，仍能正确回到正面（沿用现有语义），且与切换动画合并为一次连贯动画。
- 快速连续切换时不出现空白、卡顿或两张卡重叠。
- 导出的分享页保持同样的切换手感。

## 3. 非目标

- 不引入触摸拖拽 / 滑动切卡手势（现有 `touchstart` / `touchmove` 仅用于区分点击与滚动，不扩展为手势识别）。
- 不改变翻面动画的时长与曲线（保持 `.card` 的 `transition: transform 0.6s cubic-bezier(0.23, 1, 0.32, 1)`）。
- 不改变非切换路径的渲染行为：进入学习页、联网补全后刷新、启动回填后刷新仍为瞬间替换。
- 不引入构建步骤、依赖或持久化字段。

## 4. 关键设计决策

### 4.1 核心冲突：animation 与 transition 不能叠加

`.card`（第 136–151 行）当前的翻面机制是「`transition: transform 0.6s` + `.card.flipped { transform: rotateY(180deg) }`」。

CSS 中**动画（animation）会整体接管该属性的过渡**，动画播放期间 `transition` 不生效，两者无法叠加。
因此「翻回正面 + 横向滑出」必须是**同一段动画自己带上 `rotateY`**，不能指望原有的 0.6s 翻面过渡参与。

### 4.2 实现形态：新增 switchTo，不动 renderWord

`renderWord(index)` 现有 8 处调用，其中 3 处**必须保持瞬间替换**（见 3. 非目标），
因此 `renderWord` 保持原样，新增 `switchTo(index, direction)` 专供切换入口使用。这是本次改动的接缝。

用 **Web Animations API** 分两拍播放，而不是纯 CSS class：

| 拍 | 时长 | 缓动 | 效果 |
| --- | --- | --- | --- |
| 退出 | 130ms | `ease-in` | 卡片沿切换方向滑出 + 淡出；同时 `rotateY` 从当前角度收敛到 0° |
| 换内容 | — | — | 卡片不可见时调用 `renderWord`，并清除 `flipped` |
| 进入 | 220ms | `cubic-bezier(0.22, 1, 0.36, 1)` | 卡片从反方向滑入 + 淡入 |

合计约 350ms。位移量固定为卡片宽度的 **8%**（`translateX(±8%)`，百分比以卡片自身宽度为基准，
窄屏与宽屏观感一致），退出与进入方向相反。

换内容发生在卡片不可见的那一瞬间，因此不会看到文字跳变；
这也天然覆盖「在背面时切换」：退出拍把 `rotateY` 从 180° 转到 0°，新卡正面滑入。
**未翻转时** `rotateY` 全程为 0°，只做位移与淡入淡出。

选择 Web Animations API 而非纯 CSS class，是因为需要在两拍之间精确插入「换内容」这一步，
并能在连按时同步取消（`animation.cancel()`），纯 CSS class 做不到这两点。

### 4.3 切换期间关闭原有过渡

给 `.card` 临时加 `.switching` class（`transition: none`），否则第 143 行的 0.6s 过渡会与动画抢 `transform`，出现拖尾。
动画结束（或取消）后摘掉该 class。

### 4.4 方向语义

| 入口 | 方向 |
| --- | --- |
| 顺序切换按钮 | 恒为向前 |
| ← → 方向键 | 左键向前、右键向后 |
| 页码跳转 | 按目标页与当前页的大小比较 |
| 随机切换 | 按目标页与当前页的大小比较（随机无前后概念，用比较法避免为它单开分支） |

**绕回按入口语义定，不按大小比较。** 顺序切换在最后一张会绕回第 1 张，此时目标页序号比当前页**小**；
若按大小比较会被判成「向后」，与按钮语义矛盾。方向键绕回同理。
代价是切换入口需显式传入方向，不能全靠比较 —— 这是有意为之。

### 4.5 边界情况

- **只有 1 个词 / 目标页即当前页**：顺序切换在单张卡上会绕回自身，此时「滑出再滑入同一张卡」
  是无意义抖动。判定为 **目标页等于当前页时不播动画**，直接重渲染。
  `随机切换` 本身已有 `wordsData.length < 2` 守卫，不重复处理。
- **快速连按**：用模块级「切换中」标记。动画未播完又来新切换 → 立即 `cancel()` 当前动画、
  瞬间换内容、不播动画。保证卡片始终可见、词条即时刷新。
- **切换时正在播发音**：不打断。发音是独立 `Audio` 对象，与卡片动画无关。
- **非切换路径**（进入学习页 / 联网补全后刷新 / 启动回填后刷新）：保持瞬间替换，不走动画。

### 4.6 减弱动效

`prefers-reduced-motion: reduce` 时直接瞬间替换、不播动画。

注意：既有的 `@media (prefers-reduced-motion: reduce)` 块（第 1128 行）只能压缩 CSS 过渡，
**管不到 Web Animations API**。因此这一条必须在 JS 里用
`window.matchMedia('(prefers-reduced-motion: reduce)').matches` 判定（文件已在第 3147 行等处用过 `matchMedia`，
用法一致），命中则 `switchTo` 退化为直接调用 `renderWord`。

### 4.7 分享页

`buildShareScript`（第 2433 行）生成的是一套自包含的独立脚本，有自己的 `render` 与切换逻辑，
需要补同一段切换逻辑。`buildShareHtml` 复制的是整块 `<style>`，因此新增的 `.card.switching` 规则自动带上；
动画本身由 JS 驱动，不依赖额外 CSS，所以分享页只需同步 JS 部分。

## 7. 风险

- **两拍之间换内容是时序敏感的**：若「换内容」与「进入」两拍未对齐，会闪出旧卡内容。
  实现时须在退出拍的 `finish` 回调里同步换内容后再启动进入拍。
- **`.switching` 未及时摘除会永久禁用翻面过渡**。动画的 `finish` 与 `cancel` 两条路径都要摘除，
  建议用统一的收尾函数，避免遗漏。
- **真机 WebView（Android / iOS）表现未验证**，本机无设备；与既有多数改动的验证边界一致。
